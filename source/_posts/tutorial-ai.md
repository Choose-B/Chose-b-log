## Introduction

在`ChoseB`给27级的新同学面试时，有向多位同学问一个问题:  
> 据你了解，AI在嵌入式领域能够做到哪些事情？你觉得AI给出的回答的可靠性如何？

所有同学在`AI能够做到什么事情`这个问题上的回答非常一致，**能够生成代码，回答问题**。在可靠性的回答上，不同同学的回答却不一样。有的同学觉得AI生成的东西并没有那么可靠，好多时候是在胡扯;也有同学觉得AI生成的东西是可靠的，至少比他自己强。  
如果我说，AI能够做到的，**不止**生成代码呢？比如，能够**自行编译代码，烧录**，还有**进入调试查看程序卡在了什么地方**。甚至，**自行设计多维度的测试方案，并自主进行测试任务并迭代代码质量**？  

本文将介绍`ChoseB`自己在过去一年使用AI的经验。别着急，`ChoseB`在一开始也不熟悉AI，一直到去年寒假都是采取古法编程的。经验是都是自己摸索出来的，而不能只靠他人的知识输出。  

# 基本概念
在介绍主流的这些AI之前，有必要先给大家介绍AI的一些基本概念，给大家扫扫盲。  
很多同学对AI的印象就是"网页上的一个聊天框"，但实际上我们平时说的"AI"，是由好几层东西叠起来的。把这几层分清楚，后面讲各家AI的区别、讲AI怎么自己去编译烧录的时候，就不会糊涂了。

## Model

**模型（Model）**，准确地说是**大语言模型（Large Language Model, LLM）**，是整个AI最核心的部分，也就是大家常说的"AI的大脑"。比如`Claude Opus`、`GPT`、`DeepSeek`、`Qwen`这些名字，指的都是模型。

模型做的事情说起来非常朴素：**根据前面已有的文字，预测接下来最可能出现的文字**，一个接一个地往下"续写"。只不过因为它在海量的文本（书籍、网页、代码……）上训练过，这种"续写"的能力强到了能写代码、做推理、回答问题的程度。

理解模型，有几个概念需要知道：

* **Token**：模型并不是按"字"或"单词"来处理文本的，而是按Token。一个Token可能是一个汉字、半个单词、或者一段常见的字符组合。AI服务的计费、长度限制，基本都是以Token为单位计算的。
* **上下文窗口（Context Window）**：模型一次能"看到"的Token数量上限。你发的消息、它的回复、你贴进去的代码和报错，全部都要塞进这个窗口里。超出窗口的内容，模型就**看不到**了——这也是为什么聊得太久之后，AI会"忘记"你一开始说过的话。
* **知识截止日期（Knowledge Cutoff）**：模型训练完成后，它的参数就固定下来了。训练数据截止到哪一天，它就只知道那天之前的事情。新出的库、新版本的HAL库API，它可能根本不知道。
* **幻觉（Hallucination）**：模型的本质是"预测最可能的下一个Token"，而不是"查询事实"。所以当它不知道答案的时候，它不会说"我不知道"，而是**一本正经地编一个看起来很合理的答案**，比如编造一个根本不存在的寄存器名或者函数。

{% note warning %}
回到开头的问题：AI给出的回答可靠吗？  
单纯从模型的角度讲，**模型输出的是"看起来合理"的内容，而不是"保证正确"的内容**。模型越强，"看起来合理"和"真的正确"重合得越多，但永远不会完全重合。所以AI写的代码，一定要经过**验证**——编译能不能过、上板能不能跑、结果对不对。  
而后面我们会看到，"验证"这件事，其实也可以交给AI自己去做。
{% endnote %}

另外，同一家厂商通常会提供多个不同档次的模型：大模型更聪明但更慢更贵，小模型更快更便宜但能力弱一些。还有一类**推理模型（Reasoning Model）**，会在回答前先"思考"一段（也就是你在一些AI界面上看到的"思考过程"），在数学、调试这类需要多步推理的问题上表现更好。

但是请注意：**模型本身只能输入文字、输出文字**。它没有手，不能打开你的工程文件，不能运行`make`，更不可能去烧录STM32。那它是怎么做到这些事情的呢？这就要靠下一层：Harness。

## Harness

`Harness`这个词的本意是**马具、挽具**——马本身力气很大，但要套上挽具，这股力气才能拉动车子。AI里的Harness也是同样的意思：**它是包在模型外面的一层程序，负责把模型的"思考能力"转化成实际能做的事情**。

一个Harness通常负责这些事情：

* **管理上下文**：把系统提示词（System Prompt）、你的消息、历史对话、文件内容等组织好，喂给模型；上下文快满的时候还要负责压缩、总结。
* **提供工具（Tools）**：告诉模型"你可以用这些工具"，比如读文件、写文件、执行终端命令、搜索网页等。
* **执行工具调用**：模型本身不会真的去执行命令，它只会输出一段"我想调用某某工具，参数是什么"的请求。**真正去执行的是Harness**，执行完再把结果交还给模型。
* **权限控制**：哪些操作可以直接做，哪些操作（比如删除文件、`git push`）需要先问过你。

以"让AI编译一下工程"为例，实际发生的过程大概是这样的：

```markdown
你：     帮我编译一下这个工程，看看有没有报错
模型：   （输出）调用工具 Bash，命令：make -j8
Harness：（真正在你的电脑上执行 make -j8，把编译输出交回给模型）
模型：   （看到报错）main.c 第 42 行有个未声明的变量，
         调用工具 Edit，修改 main.c ……
Harness：（执行修改，返回结果）
模型：   调用工具 Bash，命令：make -j8
Harness：（执行，返回"编译成功"）
模型：   编译通过了，我修复了 main.c 中的一个未声明变量。
```

可以看到，**模型负责"想"，Harness负责"做"**。

常见的Harness有：

| Harness | 形态 | 能做的事 |
|--|--|--|
| 网页/App聊天界面 | 浏览器、手机App | 对话、上传文件、联网搜索等，一般**碰不到你的电脑** |
| `Claude Code`、`Codex CLI` 等 | 终端命令行 | 直接读写你的工程文件、执行终端命令 |
| `Cursor`、`GitHub Copilot` 等 | 集成在编辑器/IDE里 | 补全代码、在编辑器里修改文件、执行命令 |

除了内置的工具，很多Harness还支持通过**MCP（Model Context Protocol）** 接入外部工具。MCP可以理解为给AI用的"通用接口标准"，只要某个软件提供了MCP服务，AI就能调用它。比如接上调试器相关的MCP，AI就能自己去烧录程序、打断点、读变量——开头说的"进入调试查看程序卡在了什么地方"，就是这么实现的（后面会详细介绍MCP）。

{% note info %}
**同一个模型，套上不同的Harness，能力会天差地别。**  
在网页上用Claude聊天，和在终端里用Claude Code写代码，背后可能是同一个模型，但前者只能给你一段代码让你自己复制粘贴，后者能直接改好你的工程并编译验证。很多同学觉得"AI只能生成代码"，很大程度上是因为只接触过聊天界面这一种Harness。
{% endnote %}

## Agent

有了能思考的模型，又有了能执行操作的Harness，把它们放到一个**循环**里，就得到了**智能体（Agent）**。

Agent的工作方式可以概括为一个循环：

1. **观察**：看当前的状态（代码长什么样、编译输出是什么、串口打印了什么）
2. **思考**：判断离目标还差什么，下一步该做什么
3. **行动**：调用工具去做（改代码、编译、烧录、读变量）
4. 回到第1步，直到**目标完成**，或者遇到需要人来决定的问题

和普通的聊天最大的区别在于：**普通聊天是一问一答，每一步都要你来推动；Agent是你给一个目标，它自己决定中间的每一步**。

举个嵌入式的例子，假如你想让一个电机的速度环跑起来：

* **聊天模式**：你问AI → AI给你一段代码 → 你复制进工程 → 你编译 → 报错了，你把报错贴回去 → AI改代码 → 你再复制、再编译、再烧录 → 电机不转，你描述现象给AI → ……  
  在这个过程里，**你才是那个在循环里来回跑腿的人**。
* **Agent模式**：你告诉AI"让3号电机的速度环跑起来，目标转速1000rpm" → AI自己读工程代码、写控制代码、编译、烧录、通过调试器读取电机的实际转速、发现超调太大就调整参数、再烧录验证…… → 最后告诉你结果和它做了哪些改动。  
  **你只需要定目标、审结果。**

开头说的"自行设计多维度的测试方案，并自主进行测试任务并迭代代码质量"，就是Agent在做的事情。

{% note danger %}
Agent能自己动手，也就意味着它**可能自己动错手**：改坏代码、删错文件、烧录了错误的程序，甚至在电机上跑出危险的参数。所以使用Agent的时候：
* 用`git`管理代码，随时可以回退
* 认真看它要执行的危险操作，不要无脑全部同意
* 涉及电机、电源等实物时，做好物理上的安全措施
* **最终对代码负责的是你，不是AI**
{% endnote %}

## Skill

**技能（Skill）** 可以理解为给AI准备的**操作手册**。

模型虽然知识面很广，但它不知道**你的**做事方法：你的工程怎么编译、用的是哪个下载器、调试串口时要先检查什么、出了问题按什么顺序排查……这些经验，每次都在对话里重新交代一遍很麻烦，而且很容易漏。Skill就是把这类"某一类任务该怎么做"的经验写成文档，让AI在需要的时候自己去翻。

一个Skill就是一个文件夹，核心是里面的`SKILL.md`文件：

```markdown
---
name: usb-serial-debug
description: 诊断和验证 Linux 主机与嵌入式目标板之间的 USB CDC 虚拟串口通信，
  包括枚举、tty 设备识别、权限、原始字节抓取等。在检查 ttyACM 设备、
  CDC 枚举或上下位机通信时使用。
---

# USB Serial Debug

用可观察的证据验证整条链路：固件发出已知的数据帧，Linux 枚举出正确的
CDC 接口，主机抓到完全一致的字节。不要仅凭"枚举成功"就认为通信正常。

## 找到正确的设备
1. 查看固件 USB 描述符中的 VID、PID、产品名……
2. 与 `lsusb`、`/dev/serial/by-id` 的结果对照……
3. 不要把调试器（DAPLink/ST-Link）的虚拟串口和目标板自己的 USB CDC 搞混……
```

* 开头的`name`和`description`是Skill的"目录"，告诉AI这个Skill叫什么、**什么时候该用**；
* 下面的正文就是具体的操作步骤、注意事项、常用命令；
* 文件夹里还可以放脚本、参考资料等附属文件，正文里引用到时AI会自己去读。

Skill最关键的设计是**按需加载**：Harness启动时，只会把每个Skill的`name`和`description`放进上下文；只有当AI判断当前任务用得上某个Skill时，才会去读它的完整内容。所以即使你装了几十个Skill，也不会把宝贵的上下文窗口塞满。

{% note info %}
Skill和Claude Code里的`CLAUDE.md`（Codex里对应的是`AGENTS.md`）有点像，区别在于：
* `CLAUDE.md`是**项目说明书**，放在工程根目录，**每次都会加载**，写的是"这个工程是什么样的"；
* Skill是**任务手册**，**用到才加载**，写的是"某一类事情该怎么做"，可以跨项目复用。
{% endnote %}

Skill可以放在用户目录下（比如Claude Code的`~/.claude/skills/`，所有项目通用），也可以放在工程目录下（`.claude/skills/`，跟着仓库走，队友clone下来就能用）。Skill的格式现在也被Codex等其他Harness支持，写一份可以在多个工具里用。

那Skill怎么写呢？最省事的方法是：**和AI一起把一件事做成功之后，让它把过程总结成Skill**。踩过的坑、最终有效的步骤，都会被记录下来，下次遇到同样的问题，AI就能少走弯路。

## MCP

前面在Harness部分简单提过**MCP（Model Context Protocol，模型上下文协议）**，这里展开讲一讲。

在MCP出现之前，如果你想让AI操作某个外部软件（比如调试器、飞书、浏览器），就得给**每个Harness**单独写一套对接代码：给Claude Code写一套，给Cursor写一套，给Codex再写一套……N个工具 × M个Harness，工作量爆炸。

MCP做的事情就是**统一接口**。用嵌入式的同学最熟悉的东西打个比方：MCP之于AI，就像**USB**之于电脑。在USB出现之前，鼠标、键盘、打印机各有各的接口；有了USB之后，设备只要按USB协议实现，插到任何电脑上都能用。MCP也一样：一个软件只要实现了MCP服务，就能接入任何支持MCP的Harness。

MCP的结构分为两端：

* **MCP Client**：内置在Harness里，负责连接MCP Server，并把Server提供的工具告诉模型；
* **MCP Server**：一个单独的程序，对外提供一组**工具（Tools）**。每个工具都有名字、功能描述和参数格式。

对模型来说，MCP Server提供的工具和Harness内置的读文件、执行命令这些工具**没有区别**，都是"输出一个调用请求 → Harness去执行 → 拿到结果"。

以调试器为例，一个调试器的MCP Server可能会提供这样一些工具：

| 工具 | 作用 |
|--|--|
| `flash_program` | 把编译好的固件烧录到板子上 |
| `debug_start` / `debug_control` | 启动调试、暂停、单步、继续运行 |
| `debug_breakpoints_update` | 设置/删除断点 |
| `variables_read` | 读取全局变量的当前值 |
| `fault_read` | 读取HardFault等异常信息 |
| `rtt_read` | 读取RTT输出的日志 |

接上之后，你只需要说"程序跑一会就卡死了，帮我看看卡在哪"，AI就能自己烧录、运行、暂停、读取调用栈和异常寄存器，然后告诉你是哪里进了HardFault。

在Claude Code里添加一个MCP Server只需要一条命令，比如：

```bash
# 本地程序形式的 MCP Server（通过标准输入输出通信）
claude mcp add 名字 -- 启动命令 参数...

# 远程服务形式的 MCP Server（通过 HTTP 通信）
claude mcp add --transport http 名字 https://服务地址/mcp

# 查看已添加的 MCP Server
claude mcp list
```

{% note warning %}
使用MCP时需要注意：
* **MCP Server是在你电脑上运行的程序，或者是会接触你数据的第三方服务**，只安装可信来源的MCP，和安装其他软件一样谨慎；
* MCP返回给AI的内容（网页、文档、消息）可能夹带恶意指令，诱导AI去做你没让它做的事情，涉及敏感操作时要留意AI在干什么；
* 每个MCP工具的描述都会占用上下文，装太多用不上的MCP会白白消耗Token，用不上的可以关掉。
{% endnote %}

最后区分一下Skill和MCP：

| | Skill | MCP |
|--|--|--|
| 给AI的是 | **经验**：某件事该怎么做 | **能力**：能做以前做不了的事 |
| 本质 | 一份文档（加上可选的脚本） | 一个提供工具的程序/服务 |
| 比喻 | 操作手册 | 新的工具/手脚 |

两者经常搭配使用：调试器MCP让AI**能**烧录和调试，调试流程的Skill让AI**知道**遇到卡死时先查什么、再查什么。

# 常见AI服务提供商
需要注意的是，虽然各家AI服务提供者都会同时提供他们的`Model`和`Harness`服务，但是通常只有`Model`是收费的。多数`Harness`是免费的甚至是开源软件，且`Model`和`Harness`也没有按照厂商绑定的关系。故下面分开介绍两类服务。

### Deepseek

`DeepSeek`（深度求索）是国内的AI公司，也是国模里最有代表性的一家。目前的主力是`DeepSeek V4`系列，分为能力更强的`Pro`和更快更便宜的`Flash`两个档次。

它的几个特点：

* **便宜**：API价格在同档次的模型里低得离谱，大概只有国外头部模型的零头。若按照国外头部模型套餐的价格，其价格仍然有少量优势
* **开源**：模型权重是公开的，理论上可以自己部署（当然，以它的参数量，个人电脑是跑不动的）。
* **长上下文**：V4支持百万Token级别的上下文窗口，塞一整个工程进去也问题不大。
* **国内直连**：网页和App注册即用，不需要折腾境外网络和支付方式，对新同学来说门槛最低。

能力上，DeepSeek日常问答、解释代码、写写小函数完全够用；但在复杂的多步骤任务、大型工程的修改上，和国外头部模型相比还是有一定差距。

### GPT

OpenAI是这一轮AI浪潮的开创者，ChatGPT也是大多数人接触的第一个AI。它的特点：

* **综合能力强**：问答、写作、编程、数学、看图都比较均衡，属于"六边形战士"。
* **多档次模型**：同一代模型通常会分出不同的档次，高档的推理更强但更慢更贵，低档的适合简单任务。
* **生态完善**：除了聊天，还有联网搜索、图片生成、语音对话等功能，以及后面要介绍的`Codex`。
* **使用门槛**：官方没有在中国大陆提供服务，需要境外的账号和付费方式；免费版能用的模型和额度都有限，正经使用基本要订阅。

对于提供了套餐的国外模型来说，订阅其套餐会明显比直接使用api便宜得多。目前有两种主流办法去订阅套餐
* 苹果礼品卡。这需要你有苹果帐号，具体`ChoseB`也不清楚，因为`B`根本就没有苹果设备。有苹果设备的可以去自行摸索一下
* 谷歌Play订阅。可以参考一个[B站教程](https://www.bilibili.com/video/BV1kN7n63EhM)。如果你有谷歌帐号就可以使用这种方法。`B`目前就是这么办的。

对于视频中所提及的银行卡问题，招商银行的万事达卡还是不赖的，办卡成本是`ChoseB`打车去招商银行的车费。付款时该卡会直接先预扣款外币，然后按照汇率自动扣除人民币，比较方便。  
套餐一般订阅`Plus`。`Go`的用量过少，而`Pro`的价格太高而且很难用完额度。`Plus`套餐的价格为**20$/月**

**小结**：
使用GPT的门槛主要在于：
* 网络 - 能翻出去就能用上
* 帐号 - 苹果号或者谷歌号。直接创建帐号将被要求使用海外手机号验证。这很难办。
* 付款 - 办一张特定的银行卡就可以解决

对于GPT的**降智**问题，目前也没有特别好的解决办法。经验上，可以通过一下方法来减少被降智：
* 换用当前GPT**次强**的模型。主观感觉上，使用`5.6 Sol`中遇到的降智情况比使用`6.0 Astra`和`6.1 Sol`少很多。而且`5.6 Sol`能力已经比较不错了。
* 换用更干净的IP。梯子的IP由于是公共使用的，没有人能够保证没有人用梯子节点去做网络破坏——这会导致梯子节点被标记为高风险。另外，被公共使用意味着有大量的请求是从同一个IP发出的，风控一看就会知道这个IP不正常。
  * 但是如果采用vds的解决方法，虽然可以解决问题，但是都上这么大的成本了为什么不去试试Claude

### Claude

`Claude`是`Anthropic`公司的模型。Anthropic的创始团队很多来自OpenAI，公司非常重视AI安全。Claude的模型按能力分为三个档次：

| 档次 | 特点 |
|--|--|
| `Opus` | 最强，适合复杂任务和长时间的Agent工作，也最贵 |
| `Sonnet` | 能力和速度比较均衡，日常编程的主力 |
| `Haiku` | 最快最便宜，适合简单任务 |

Claude在**编程**和**Agent任务**上的口碑很好：它比较擅长理解大型工程的结构、按照指令一步步执行长任务、调用工具并根据结果调整下一步，**目前无可争议的世一模**。这也是它和后面介绍的`Claude Code`搭配起来特别好用的原因。

缺点也很明显：**贵**，**风险高**而且和ChatGPT一样，官方没有在中国大陆提供服务，**而且特别喜欢封号不退款**，其财报中明确提到其营收有5%-7%来自封号不退款的收入，注册和付费的门槛是三家里最高的。
通常订阅其`Pro`套餐。每月22$

### 中转站
**不建议使用任何中转站**，尽管你可以更轻松的用上上述顶层模型，但是你必须知道其中的常见风险:   
* **掺水**。原理上和降智一样，只不过GPT的降智是调用其内部更低级的模型，而掺水则是让更便宜的模型去替换顶层模型。例如标的是Claude但是给你提供的是大肥鱼或者豆包（
* **数据安全**。当你使用中转站时，其原理是：你本地发出的API请求不再直接发送给模型提供商，而是中转站。其中，模型所需要的上下文会全部发送到中转站处，然后再被转发到模型提供商。   
  这么做的风险是：中转站很有可能会储存这些可能包含你个人敏感信息的上下文数据，并转售
* **跑路**。中转站可能因为各种原因（圈够钱了，被政府查封，无法继续运营号池了）而跑路。你在上面支付的任何费用都不受法律保护，如果中转站跑路了几乎无法追回还没使用的金额

## Harness

前面说过，Harness决定了模型"能动手做什么"。各家除了网页/App这种聊天型Harness以外，现在都把重心放在了**编程Agent**上：让AI直接在你的电脑上读代码、改代码、跑命令。

### Deepseek Harness

DeepSeek Harness 是 DeepSeek 开源的一套 AI Agent 执行框架。虽然其“一切皆插件”的设计理念吸引了很多人去使用，但是`ChoseB`并不推荐你去使用dsh
* 不够成熟。大肥鱼在dsh中的模型表现可能不如在其他agent中的，例如Claude Code
* 网络安全漏洞。其发布初期爆出过多个严重的网络安全漏洞，攻击者可以利用dsh直接控制你的电脑。具体可见相关B站视频

### Codex

`Codex`是OpenAI推出的编程Agent，有几种形态：

* **Codex CLI**：运行在终端里的命令行工具，**开源**；
* **IDE插件**：在VS Code等编辑器里使用；
* **云端版**：把任务交给OpenAI的云端环境去跑，跑完给你提交代码。

Codex可以读写工程文件、执行终端命令、运行测试，也支持通过MCP接入外部工具。登录方式上，既可以用ChatGPT的订阅账号登录（用订阅额度），也可以用API Key按Token计费。  
默认情况下Codex会在**沙箱**里运行命令，限制它能访问的文件和网络，危险操作需要你批准，对新手来说相对安全。

### Claude Code

`Claude Code`是Anthropic推出的编程Agent。它同样有终端CLI、IDE插件（VS Code、JetBrains）、桌面App和网页版等多种形态。

Claude Code的特点在于**可扩展性**非常强：

* **MCP**：接入外部工具，比如调试器、串口、飞书等；
* **CLAUDE.md**：在工程根目录放一个说明文件，写上工程结构、编译命令、代码规范，AI每次启动都会先读它，相当于给AI的"项目交接文档"；
* **Skills**：把某类任务的操作流程打包成"技能"，需要时自动加载；
* **Hooks**：在AI执行某些操作前后自动运行你指定的脚本，比如每次改完代码自动格式化；
* **Subagent**：把子任务分派给其他AI并行处理。

付费方式上，可以用Claude的Pro/Max订阅登录，也可以用API Key按量计费。

另外，因为DeepSeek的API兼容Anthropic格式，可以通过环境变量让Claude Code改用DeepSeek的模型，用Claude Code的Harness、付DeepSeek的价格：

```bash
export ANTHROPIC_BASE_URL=https://api.deepseek.com/anthropic
export ANTHROPIC_AUTH_TOKEN=你的DeepSeek API Key
export ANTHROPIC_MODEL=deepseek-v4-pro   # 模型名以DeepSeek官方文档为准
claude
```

除此之外还有多种功能,例如监控用量，提高服务稳定性。是一个非常好用的辅助软件

# WorkFlow
那么，如何让AI形成`生成`-`编译`-`烧写调试`-`验证`-`发现问题`-`进一步生成`-`...`的闭环呢？
* 满足条件的环境。AI首先要能编译烧写调试才能完成上述逻辑闭环对吧。
  * 首先要用本地的Harness。网页版的对话窗口肯定无法帮你完成这些任务。自己挑一个Harness来用，不论是终端中的还是桌面软件式的
  * 安装相应工具。对AI来说，最顺手的工具是命令行。因此，可以下载`OpenOCD`，这是开源的调试工具。AI通过`OpenOCD`提供的命令就能够实现烧写，调试的功能
    * 可以在每次工作正式开始前，询问AI是否有相关能力;如果不行，是否是缺少了什么工具
    * `OpenOCD`只是个例子。使用其他的工具可以实现不同的功能
* 完备详细的提示词。你的提示词应该包含：
  * 工作目的
    * 要达成什么目标
    * 要使用什么方法
    * 在什么标准下，AI做的事情算“完成”
  * AI必须遵守的规则，例如
    * 不得修改无关的代码
    * 代码风格必须遵循“xx规范”
  * 可提供参考的前置内容（如果有）
    * 例如，要求AI写一份规则理解的文档，可以提供相关规则文件的文件目录，并明确要求其先阅读再动手写
* 认真严谨的人工审查
  * 尽管在以上闭环的工作流中，AI所生成内容的可靠性已经得到大大提升，但是这不等于其生成的内容就是满足要求的。
  * 只有能够理解AI在干嘛，才能让AI成为你趁手的工具

这也是为什么当下我们还注重“你到底会什么”。你对工作流程的认识越清晰完整，知识图景越广阔，基础越扎实，你越能够写出完备详细的提示词，越有能力去审查AI到底都在干什么，越有想法去驱使AI做出更有价值的内容。
